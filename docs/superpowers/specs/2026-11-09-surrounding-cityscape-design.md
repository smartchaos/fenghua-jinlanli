# 周边城市 3D 化设计

日期：2026-11-09
分支：`feat/3d-surrounding-cityscape`
参考：[ref/plan1.png](../../../ref/plan1.png)（官方航拍区位效果图）

## 背景

小区本体与其西侧运河、双桥、外围草甸已以 3D 呈现，但四周仍是 1600×1600 的空旷草甸、6 座丘陵与 7 组远山。参考图里真正构成"城市感"的是**密集的中高层楼群、街区路网、留石高架、河网与成片绿地**。本设计把这层城市肌理以程序化 3D 几何补进场景，让 HOME 视角与旋转视角都能看到小区所处的城市环境。

## 目标

- 在小区四周 250–900 单位环带生成街区级城市楼群、路网、绿化带与一条高架，空间关系对齐航拍图（南侧隔电厂河为住宅群、东侧为商务/高层、北侧为密集住宅、西侧沿运河为绿地与低层配套）。
- 远景补一层低细节城市剪影，与既有远山叠加，在雾中自然淡出。
- 保持"真 3D"：相机旋转、缩放、日夜切换下都不穿帮。
- 沿用刚完成的写实化观感与"低饱和、不抢焦点"的周边约定。

## 非目标

- 不逐栋考证真实楼盘、不还原参考图上的文字标注与区位标签。
- 不给周边建筑加可点击/悬停交互，不接入楼栋数据面板。
- 不调整相机、雾距、OrbitControls 参数，不扩大阴影贴图覆盖范围。
- 不引入外部图片/模型资源（构建仍是 Vite 单文件内联产物）。
- 不改动小区楼群、数据编码、标签、巡览、日夜模式，也不改动用户现有的未提交数据与文档。

| 项 | 值 / 位置 |
| --- | --- |

| 共面避让 | 桥面顶 `y=1.8` 与驳岸顶曾 z-fighting，新增平面必须避开既有 y 值 — `docs/2026-11-05-z-fighting-perf-fix.md` |
| 构建 | `viteSingleFile` 全内联，`npm run build` 同步到根 `model.html`（约 836KB） |

推论：日间雾在 1350 处完全遮蔽远景，因此城市主体必须落在 900 以内；远景剪影放在 900–1300 并主动接受雾化。阴影贴图只覆盖小区 ±230，新增楼群不得投射或接收阴影，否则会与冻结的阴影贴图和 ±230 范围冲突。

## 方案选择

- **A（采用）新增 `cityscape.js` 程序化街区**：InstancedMesh 生成四类楼体 + 街区路网 + 绿化带 + 高架 + 远景剪影。真 3D、draw call 可控、相机任意角度成立、可按坐标断言回归。
- **B 城市烘焙进地面/天空贴图**：成本最低，但只在固定视角成立，与"3D 方式"相悖，排除。
- **C 逐街区精模 + 完整路网**：还原度最高，但数千 draw call、单文件体积膨胀，且必须放宽雾距与阴影覆盖，破坏既有观感与功耗约束，排除。

## 设计

### 1. 架构与接口

新增单一职责模块 `app/src/three/cityscape.js`，导出 `createCityscape(scene)`，返回 `{ group, stats }`（`stats` 供测试断言：实例数、各类型数量、禁建区命中数）。`app.js` 在 `createWilds(canalGrp)` 之后调用一次，不修改其他模块的公开接口。所有布局参数集中在该模块顶部的 `CITY` 配置对象，坐标由 `constants.js` 的 `RX/RZ/SITE_W/SITE_D` 派生，禁止在几何代码里散落绝对坐标魔数。

### 2. 布局与避让

以小区中心为原点，环带半径 250–900，按 60–90 单位划分街区网格；分三段密度：近环 250–450 为 0.75、中环 450–700 为 0.5、远环 700–900 为 0.25。每个街区用确定性伪随机决定是否建楼、建几栋、楼型与朝向。生成器必须拒绝以下区域，`stats` 返回 `placed`（实际落位实例）与 `rejected`（被拒候选数）供断言：

- 小区本体与入口广场：`|x|<140 且 |z|<210`
- 京杭大运河及滨河绿带：`x ∈ [-460,-240]`
- 顾扬路：`|x-110|<25`
- 朱家坝路：`|z-150|<25`
- 电厂河：`|z+161|<28`
- 既有丘陵、远山、船、护坡树所在的包围盒
- 斜拉桥与两座跨河桥的桥面投影

南侧（`z>180`）以板楼住宅群为主，东侧（`x>140`）以点式高层与少量地标塔为主，北侧（`z<-180`）为密集住宅，西侧沿运河以绿地与低层配套为主，形成与参考图一致的空间节奏。

### 3. 几何与材质

四类楼体各用一个 `InstancedMesh`（共享 `BoxGeometry`），通过实例矩阵表达位置、朝向、宽深与高度：

| 类型 | 高度 | 形态 |
| --- | --- | --- |
| 板楼 | 18–45 | 宽 > 深，成排布置 |
| 点式高层 | 45–80 | 近方形平面，局部收分 |
| 低层配套 | 8–14 | 大占地、扁平 |
| 地标塔 | 80–120 | 细高，顶部收分，仅 3–5 处 |

立面不逐窗建模：生成一张 512×512 程序化 CanvasTexture（横向窗格明暗带 + `grainOverlay` 细颗粒），日/夜两套经 `themedMats` 切换；实例颜色用低饱和米灰/蓝灰，经 `regColor` 注册日夜两色。远景剪影使用单色 `MeshStandardMaterial`，不含贴图，靠雾淡化。

街区路网用贴地细长平面 + 程序化路面贴图（沿用 `siteTexture.js` 的画法），绿化带用 `flatMat` 低饱和绿块并点缀少量实例化树球；这两类平面统一置于 `y=-0.30`（高于草甸 -0.35、低于水面 0.06 与场地 0/3.0），不与 `y=0 / 0.02 / 0.06 / 1.8 / 3.0` 共面。留石高架沿参考图横向主干道布置：带状桥面 `y≈8`、等距桥墩，桥面顶避开 `y=1.8` 等既有共面值。所有新增几何 `castShadow=false`、`receiveShadow=false`，不进入 `buildings.pickMeshes`。

### 4. 主题与渲染预算

- 确定性种子复用 `app/src/three/rng.js`，保证每次构建一致、可截图回归。
- 颜色与贴图全部经 `regColor` / `themedMats` 接入 `applyFaders`，日夜切换行为与现有周边一致。
- 预算：≤12 个 `InstancedMesh`、≤20 个额外 draw call、`model.html` 增量 ≤60KB。
- 不改动 `needsRender` 逻辑与 `shadowMap.autoUpdate=false`；闲置仍零渲染。
- 不新增 RAF 回调、不新增逐帧更新。

### 5. 验收

- 新增 `scripts/check-cityscape.py`（Playwright + Chrome，与 `scripts/check-realism.py` 同构）：断言 `stats.placed` 达下限、四类楼型均存在、所有已落位实例都不在禁建区内、日夜切换无 JS 报错、draw call 增量 ≤20、闲置时 `renderer.render` 调用为 0。
- 现有 `scripts/check-realism.py`、`scripts/check-model.mjs`、`scripts/validate-layout.mjs` 全部不回归。
- 四个视角截图（HOME / 东侧 / 南侧 / 夜间）人工比对 `ref/plan1.png` 的空间关系与低饱和调性。
- 扫描新增平面 y 值，确认与既有桥面/驳岸/水面无共面。
- `npm run build` 同步根 `model.html`，并对产物重跑浏览器断言。

### 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 雾吃掉远景城市 | 主体限制在 900 以内；剪影放 900–1300 并接受雾化；不动雾参数 |
| 阴影贴图冻结且范围仅 ±230 | 新增几何不投射/不接收阴影 |
| 与既有丘陵、树丛、桥梁重叠 | 显式避让清单 + 生成器拒绝计数 + 浏览器断言 |
| 单文件体积膨胀 | 全部程序化生成，无外部贴图；预算 ≤60KB 增量 |
| 拉远视角穿帮 | 保持 `maxDistance=620`、雾距与相机参数不变 |
| 周边抢走小区焦点 | 沿用 `wilds.js:70` 的低饱和约定，楼群明度低于小区立面 |

## 明确不动

小区楼群与琥珀/蓝窗数据编码、楼名标签、点击/悬停/巡览、日夜模式、相机与雾参数、阴影配置、按需渲染逻辑、用户未提交的数据与文档改动。
